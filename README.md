# 测斜监测管理系统

基坑测斜数据的录入、计算、预警与更正追溯系统。

- 后端：Node.js 20 + TypeScript + Fastify，计算全部在后端完成
- 存储：PostgreSQL 16
- 前端：Vue 3 + Vite + ECharts，构建后由应用服务托管（单端口）
- 测试：Vitest（纯内存仓库，无需数据库）

## 启动

```bash
docker compose up --build
# 打开 http://localhost:3000
```

首次启动应用会自动执行数据库迁移（`packages/server/src/storage/schema.sql`，幂等）。

本地开发：

```bash
npm install
npm run build:shared
docker compose up -d postgres            # 或自备 Postgres
npm run dev:server                       # http://localhost:3000
npm run dev:web                          # http://localhost:5173 （代理 /api）
npm test                                 # 后端测试
```

## 计算模型

### 测点与测段

读数按深度升序给出，深度必须为 `spacing, 2·spacing, …, depth`，等间距且与孔深相符。
第 i 个读数行（深度 d_i = i·L）对应测斜仪在该深度测得的、位于该测点与其上方测点之间的测段；
最深一行（d = 孔深）的测段底端视为**孔底固定点**（位移为 0）。

对每个深度：

- `tilt_i = (正测 − 反测) · factor`（factor 取该深度正/反测所用探头在测量时刻生效系数的均值）
- 段水平偏移 `s_i = tilt_i · L`（小角近似，正弦值即水平偏移/段长）
- 从孔底固定点往上逐段累加：测点 i 的原始累计 `C_i = Σ_{j≥i} s_j`
- 相对本基准段初始测量：`R_i(m) = C_i(m) − C_i(base)`
- 位移单位 mm，深度单位 m，速率单位 mm/d

小算例验证（测试 `engine.test.ts`）：三个测段（L=0.5 m）从孔底往上相对初始的
倾斜正弦为 0、0.004、0.002 时，三个测段顶端的累计位移依次为 0、2 mm、3 mm。

物理对称性（同一测试文件）：

- 读数与初始测量完全相同 → 相对位移处处为 0
- 探头系数翻倍、读数不变 → 位移翻倍
- 正/反测读数互换 → 位移变号

### 校核和与可疑点

`checksum_i = 正测_i + 反测_i`。理想情况下同一根管子各深度的和近似常数。
以同孔全部深度的**中位数**作为该常数的稳健估计，以 MAD 估计离散度：

```
可疑 ⇔ |checksum_i − median| > checksumTolerance + 3 · 1.4826 · MAD
```

可疑点**只标记、不自动剔除**，在测量详情页黄底标出。MAD 为 0 时退化为固定容差，
干净数据不会误报；单个离群点可被检出。

### 速率与预警分级

相邻两次测量（按时间排序）之间：

```
rate_i = (位移_i(本次) − 位移_i(上次)) / (两次测量间隔天数)
```

孔可按深度配置蓝/黄/红阈值（mm/d），代表深度之间线性插值，两端取边界值；
每一行必须 蓝 < 黄 < 红（录入时拒收非递增）。各深度按 `|rate|` 定级，
一次测量的等级取所有深度的最高等级。同孔测量时刻必须唯一。

## 基准（datum）——关键设计决策

以下三种事件产生**新的基准段**，在上传时显式标记：

1. 测斜管受损修复（`tube_repair`）
2. 更换探头（`probe_change`）
3. 正式重设初始测量（`manual_reset`）

孔的第一次测量自动成为第 0 段基准。每段内部，相对剖面 = 本次原始累计 − 段内第一次测量的原始累计。

### 跨段如何接起来：**相邻两次测量的逐深度差异取中位数，作为标量系统偏移**

设新段 k 的第一次测量为 `reset_k`（修复/换探头当天的复测），上一段 k−1 的最后一次测量为 `last_{k−1}`。
认为这两次紧邻测量之间**没有真实位移**，它们在每个深度的差异全部来自换探头/修复引入的
系统零漂，于是：

```
delta_d  = R_d(last_{k−1}) − R_d(reset_k)     （reset 的段内相对剖面处处为 0，
            实际就是旧段最后一次的逐深度相对位移）
anchor_k = anchor_{k−1} + median_d(delta_d)
connected(m, d) = anchor_{group(m)} + R_d(m)
```

剖面图上用**红色虚线**标出每个基准切换位置，并悬浮显示段号、切换日期和拼接偏移量；
跨基准计算出的速率逐点打 `crossDatum` 标记。实现见 `engine/compute.ts`。

### 为什么选这个方案，代价是什么

备选方案对比：

- **方案 A：直接把旧段最后一次的逐深度累计值叠加到新段。**
  实现最简单，但旧段末测曲线上的任何异常（坏点、局部漂移形状）会原样“冻”进新段，
  并且默认修复/换探头前后零系统差，现实中几乎不成立。
- **方案 B（本系统采用）：相邻两次测量的逐深度差异取中位数作为标量偏移。**
  中位数是对逐深度偏移的 L1 最优单一常数估计，对个别坏点稳健；它表达的假设是
  “零漂主要表现为整孔一致的常数偏置”。
- **方案 C：逐深度各自对齐（每个深度自己的偏移）。**
  会把旧段末测的整条曲线（含真实位移形状）全部抹掉，且让真实的渐进位移被误判为系统差，不可取。

方案 B 的代价（明确告知使用者）：

1. 探头零漂若随深度呈**线性/弯曲形状**（而非常数），标量只能匹配中位深度，
   残余斜率会作为“表观倾斜”留在新段曲线里。系统不尝试拟合斜率，因为在只有一对
   相邻测量时无法区分“线性漂移”与“真实的线性变形”，强行扣除更危险。
2. 假设修复/换探头当天的复测与上一测之间无真实位移。若这段间隔内确有变形，
   该变形会被并入拼接偏移（位移被吃掉一次），但其后的速率不受持续影响。
3. 跨基准的第一条速率在图上明确标记 `crossDatum`，提醒判读时谨慎，不做自动静默处理。

## 更正、版本与历史判级

- **测量与标定都是版本化实体**，更正走乐观并发控制（CAS）：
  `UPDATE … WHERE revision = baseRevision`。两人同时基于同一版本更正时，一笔成功、
  另一笔得到 409 冲突提示，绝不静默覆盖；失败者取新版本后可重试。
- 每次计算结果以**内容指纹**（与测量修订号、计算时间无关的曲线/速率/等级序列化哈希）
  存入 `computed_snapshots`；内容不变不新增行。
- 因此系统可同时回答：
  - “按当时数据，这次判几级”——取 `computed_at ≤ asOf` 的最后一个快照；
  - “按现在数据应该判几级”——取最新快照。
  - 两者不同时，测量详情页并排展示并高亮差异（`GET /api/measurements/:id/history?asOf=…`）。
- **补录**一次测量到已有两次之间：所有受影响的相邻测量对的速率按新时间顺序重算，
  受影响结果写新快照，旧快照保留。
- **更正测量或标定**：
  - 测量读数/时间/探头/基准标记变更 → 该孔重算，速率沿相邻顺序级联；
  - 标定新增（含补录早期生效版本）或更正 → 所有使用该探头的孔重算。

### 增量 ≡ 全量（硬性不变量）

`engine/compute.ts` 的增量路径实现为：**全量重算 + 逐结果指纹比对**——
输入指纹（读数、时间、基准标记、在测量时刻生效的标定系数）未变的结果标记 `unchanged` 复用，
只对变化结果写快照；服务层在每次重算时都额外断言增量结果与全量结果序列化相等，
不一致直接抛错（`monitorService.recomputeBorehole`）。测试
“更正后增量结果与全量重算完全一致”验证：更正后强制全量重算不再产生任何新快照，
且服务内断言通过。

## 拒收的输入（422，带具体字段）

- 深度序列不等间距、不在 spacing 网格上或与孔深不符；同一深度出现两次
- 正测/反测读数不是有限数（NaN/Infinity 拒绝）
- 测量日期早于该孔初始测量；同孔测量时刻重复
- 探头编号没有登记（含逐行覆盖的探头）
- 阈值不是严格递增（蓝 < 黄 < 红）
- 标定系数非正；时间无法解析；缺字段

## 测试

`npm test`（16 个用例，覆盖需求点名的全部场景）：

- 三测段 0/2/3 mm 算例；首次测量相对位移为 0
- 读数相同位移处处为零；系数翻倍位移翻倍；正反测互换位移变号
- 校核和干净数据无可疑点、单点异常标记但不剔除
- 更正后增量结果与全量重算一致（快照数不增加）
- 补录中间测量，前后速率按新顺序重算
- 并发更正只生效一次 + 冲突错误，重试可成功
- 历史判级可查，蓝 → 红的当时/现在差异
- 全部五类拒收输入及具体字段
- 换探头基准段的中位数拼接与边界标记
