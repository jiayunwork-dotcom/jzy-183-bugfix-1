# 基准（datum）拼接决策

本文件说明跨基准段如何把各段的相对剖面接成一条连续剖面。实现见
`packages/server/src/engine/compute.ts`（`buildRelatives / buildAnchors / buildConnected`）。

## 背景

以下三种事件产生**新的基准段**，在录入时显式标记：

1. 测斜管受损修复（`tube_repair`）
2. 更换探头（`probe_change`）
3. 正式重设初始测量（`manual_reset`）

孔的第一次测量自动成为第 0 段基准。段内第 m 次测量在深度 d 的相对剖面：

```
R_d(m) = C_d(m) − C_d(base)          C = 从孔底固定点往上的原始累计位移
```

段内基准自身的 R 处处为 0。跨段需要给每段一个偏移 `anchor`，使

```
connected(m, d) = anchor[group(m)][d] + R_d(m)
```

## 决策：逐深度对齐（向量 anchor）

设新段 k 的第一次测量为 `reset_k`（修复/换探头当天的复测），上一段 k−1 的最后一次
测量为 `last_{k−1}`。**认为这两次紧邻测量之间没有真实位移**，它们在每个深度的差异
全部来自换探头/修复引入的系统差（探头零漂、管型改变），于是**逐深度**对齐：

```
anchor[k][d]    = anchor[k−1][d] + R_d(last_{k−1}) = connected(last_{k−1}, d)
rawOffset[k][d] = C_d(reset_k) − C_d(last_{k−1})   （被吸收的逐深度原始差异，诊断用）
```

- `anchor[0][d] = 0`，第 0 段不动。
- `anchor` 是**与各测点同序的向量**，不是单个标量；孔底固定点在新段的
  anchor 等于上一测孔底的连续位移（通常为 0），固定点不会凭空漂走。
- 换探头当天的跨段速率逐点为 0，不触发预警；逐点仍打 `crossDatum` 标记供判读。
- `rawOffset` 随基准边界返回（叠加接口 `boundaries[].rawOffset`），展示被吸收的
  逐深度差异形状，便于事后核对“吃掉”的是不是零漂。

### 为什么不用标量（中位数）偏移

换探头的常数零漂作用在**每个测段**上，反映到累计剖面上是从孔底往上逐段累积的
线性形状，而不是整孔常数偏置。复现场景（孔深 2 m、间距 0.5 m，新探头每段 0.002
常数零漂）中，新基准原始累计与旧末测的逐深度差异是 `[4,3,2,1]`，中位数只有 1：
标量对齐后当天剖面变成清一色 1 mm、孔底固定点漂到 1 mm，跨段速率出现
`[−1.5, −0.5, +0.5, +0.5] mm/d` 的假速率并误挂蓝警；其后整条曲线也带着残余斜率，
和换探头前的剖面接不起来。只有逐深度向量能整体抵消这种随深度变化的系统差。

## 备选方案与取舍

- **方案 A：直接沿用旧段末测的整段累计（零偏移拼接）。**
  实现最简单，但默认修复/换探头前后零系统差，现实中几乎不成立；常数零漂会原样
  留在新段，产生假速率和误警。（本次修复前的线上行为等价于此 + 段内基准清零。）
- **方案 B：逐深度差异取中位数作为标量偏移。**
  中位数是对逐深度偏移的 L1 最优单一常数估计，对个别坏点稳健，假设是“零漂主要
  表现为整孔一致的常数偏置”。但探头零漂在累计剖面上通常是累积形状（见上），
  标量只能对齐中位深度，残余斜率仍会误报。**已放弃。**
- **方案 C（采用）：逐深度各自对齐。**
  对任意形状的系统差（常数、线性、弯曲）都能在切换当天精确对齐，且不依赖坏点
  分布。其代价见下。

## 副作用（明确告知使用者）

1. **假设复测与上一测之间无真实位移。** 若这段间隔内确有变形，该变形会在拼接处
   被并入 anchor（位移被“吃掉”一次）；但其后的速率不受持续影响——anchor 是常数，
   差分即消去。无法区分时本系统选择不误报、保持曲线连续，而不是凭空生成假速率。
2. **逐深度对齐不做稳健化。** 旧末测某深度若有坏点，该点的异常会被冻进 anchor。
   可疑读数在录入时已用校核和/MAD 标记（只标记不剔除），应先更正再切基准；
   事后更正任一历史读数时，anchor 与所有后续剖面/速率会自动级联重算。
3. **跨段第一条速率逐点打 `crossDatum`。** 逐深度对齐后该速率为 0，不产生预警，
   但标记保留，提醒判读者这里存在基准边界。
4. **补录会改拼接。** 在 `last_{k−1}` 与 `reset_k` 之间补录一次测量时，新补入的
   一测成为上一段末测，anchor 对齐目标随之改变（这是“复测对齐到紧邻一测”的
   直接推论）；同理，连续换两次探头、或某段只有一次测量就再换时，每次对齐的都是
   时间上紧邻的前一测。

## 更正、补录与“增量 ≡ 全量”

- 拼接只依赖各测量的原始累计与基准标记。事后**更正**换探头前任一次测量的读数，
  或**补录**测量改变时间顺序时，整孔重新分段、重建 anchor 向量，后续各次的
  剖面、速率、预警等级全部级联更新。
- 旧结果以**内容快照**保留，“按当时数据判几级”取 `computed_at ≤ asOf` 的最后一个
  快照，与按当前数据重算的结果并存可查。
- 增量路径实现为“全量重算 + 逐结果指纹比对”，未变结果标 `unchanged` 复用、
  不重复写快照；服务层在每次重算时断言增量结果与全量结果序列化完全相等
  （`MonitorService.recomputeBorehole`），不一致直接抛错。因此任何时刻增量更新的
  结果都与整孔从头重算一致，anchor 改为向量不改变这一不变量。
